# RP2350 Microcontroller

**Summary**: What the RP2350 chip datasheet (release 8, build date 01/10/2026) says about GPIO voltage levels and 5 V tolerance, drive current, pull resistors, the GPIO function-select table (UART0 and I2C0 pin options), I2C speed modes, UART limits and errata. It fills the gaps listed on the [Pico 2](pico-2.md) page. The datasheet was read selectively (about 12 sections of a 1,371-page document).

**Sources**: [rp2350-datasheet](sources.md#rp2350-datasheet)

**Last updated**: 2026-10-11

---

All numbers are **spec** values from the datasheet. "Sec." is the section and "p." the printed page number. Electrical limits come from characterisation over the specified temperature and voltage range, except values the datasheet marks "Simulated" ([rp2350-datasheet §14.9, p. 1335](sources.md#rp2350-datasheet)). The Pico 2 board uses the QFN-60 RP2350A (GPIO0 to GPIO29) *(per the [Pico 2](pico-2.md) page)*; the chip also exists as a QFN-80 RP2350B with GPIO0 to GPIO47.

## Pad types and 5 V tolerance

The pin list gives GPIO0 to GPIO25 the type "Digital IO (FT)", where FT means fault tolerant. GPIO26 to GPIO29 are "Digital IO / Analogue" (standard pad shared with the ADC) and are **not** FT ([§14.8.2, Table 1673 and Table 1674, pp. 1331-1332](sources.md#rp2350-datasheet)).

| Item | Value | Conditions | Source |
|------|-------|------------|--------|
| FT pad definition | Tolerates up to 5.5 V, and very little current flows in below 3.63 V when IOVDD is 0 V | **IOVDD must be powered at 3.3 V** for the 5.5 V case | Table 1673 |
| Absolute max voltage at a standard pad | IOVDD + 0.5 V (minimum -0.5 V) | any IOVDD | Table 1680, p. 1335 |
| Absolute max voltage at an FT pad | 5.5 V | IOVDD = 3.3 V, IOVDD present | Table 1680 |
| Same, IOVDD = 2.5 V / 1.8 V | 4.2 V / 3.63 V | IOVDD present | Table 1680 |
| Same, IOVDD = 0 V | 3.63 V | chip unpowered | Table 1680 |
| IOVDD absolute max | 3.63 V (minimum -0.5 V) | | Table 1680 |
| Voltage above IOVDD on any pad | Causes leakage through the ESD protection diodes | | Table 1683 text and §6 |

The absolute maximum figure is a stress rating (damage limit), not a normal operating condition. The operating input limit is the VIH maximum in the next section, which is also 5.5 V for FT pads at IOVDD = 3.3 V.

## Input and output levels

IOVDD (the pad supply) is 1.62 to 3.63 V, typically 1.8 or 3.3 V ([Table 1688, p. 1340](sources.md#rp2350-datasheet)); the Pico 2 board fixes it at 3.3 V ([pico-2](pico-2.md)). Ambient temperature range is -40 to 85 C ([Table 1682](sources.md#rp2350-datasheet)). The values below are for **IOVDD = 3.3 V** ([Table 1683, p. 1336-1337](sources.md#rp2350-datasheet)).

| Parameter | Min | Max | Notes |
|-----------|-----|-----|-------|
| VIH, input high, standard pad | 2.0 V | IOVDD + 0.3 V | |
| VIH, input high, FT pad | 2.0 V | 5.5 V | IOVDD must be powered to tolerate above 3.63 V |
| VIL, input low | -0.3 V | 0.8 V | |
| VHYS, hysteresis | 0.2 V (min) | | Schmitt trigger enabled |
| VOH, output high | 2.62 V | IOVDD | at IOH = 2, 4, 8 or 12 mA depending on drive setting |
| VOL, output low | 0 V | 0.5 V | at IOL = 2, 4, 8 or 12 mA depending on drive setting |
| Input leakage IIN | | 1 uA | but see errata E9 below |
| Pull-up resistance RPU | 32 kohm | 86 kohm | |
| Pull-down resistance RPD | 36 kohm | 113 kohm | |
| Sum of all GPIO source current | | 100 mA | all GPIO pins together; same limit for sink |

Drive strength: four settings, nominally 2, 4, 8 and 12 mA, and the default is 4 mA ([Table 1673](sources.md#rp2350-datasheet)). The datasheet says these are not hard limits and that the actual current depends on the load, with VOH falling as the load rises ([§14.9.4.1, p. 1339](sources.md#rp2350-datasheet)). The per-pin absolute maximum current is not given as a separate figure in the parts read; only the 100 mA bank totals appear *(needs source if a per-pin limit is wanted)*.

Reset state of each GPIO pad (PADS_BANK0 register, [Table 885](sources.md#rp2350-datasheet), p. 705): input enable off, pull-down on, pull-up off, Schmitt trigger on, slow slew, and the register reset value selects the 4 mA drive setting (the pin list also says "Pull-Down" as reset state). Pad isolation (ISO) is set at reset and software removes it once the pad is configured.

## GPIO function select (UART0 and I2C0)

[Table 3 in §1.2.3, pp. 17-19](sources.md#rp2350-datasheet) lists the functions per GPIO (function select F0 to F11; F5 is SIO, F6 to F8 are PIO0 to PIO2). The function numbers below are read from the column order and agree with the register descriptions that list GPIO0 F2 as uart0_tx and F3 as i2c0_sda.

| GPIO | UART0 / UART1 option | I2C option |
|------|----------------------|------------|
| 0 | F2: UART0 TX | F3: I2C0 SDA |
| 1 | F2: UART0 RX | F3: I2C0 SCL |
| 2 | F2: UART0 CTS; F11: UART0 TX | F3: I2C1 SDA |
| 3 | F2: UART0 RTS; F11: UART0 RX | F3: I2C1 SCL |
| 4 | F2: UART1 TX | F3: I2C0 SDA |
| 5 | F2: UART1 RX | F3: I2C0 SCL |
| 6 | F2: UART1 CTS; F11: UART1 TX | F3: I2C1 SDA |
| 7 | F2: UART1 RTS; F11: UART1 RX | F3: I2C1 SCL |

All GPIOs where UART0 TX/RX and I2C0 SDA/SCL can be placed on this chip (QFN-60, GPIO0 to 29):

| Signal | GPIO numbers |
|--------|--------------|
| UART0 TX | 0, 2, 12, 14, 16, 18, 28 |
| UART0 RX | 1, 3, 13, 15, 17, 19, 29 |
| I2C0 SDA | 0, 4, 8, 12, 16, 20, 24, 28 |
| I2C0 SCL | 1, 5, 9, 13, 17, 21, 25, 29 |

The pattern repeats every four GPIOs: even-numbered pairs alternate between I2C0 and I2C1 SDA/SCL. A UART TX/RX pair must be on a matching pair (for example 0 with 1, or 12 with 13). The datasheet says some signals appear in several places for flexibility, and that a pin can have only one function at a time (one FUNCSEL per pin) ([§1.2.3, §9](sources.md#rp2350-datasheet)). Which physical pin on the Pico 2 board a GPIO number sits on is **not** in this datasheet (see [Pico 2](pico-2.md)).

## I2C

Each of the two controllers is a Synopsys DW_apb_i2c v2.03a, designed to the I2C specification version 6.0 (April 2014) ([§12.2.1, p. 892](sources.md#rp2350-datasheet)).

| Item | Value | Source |
|------|-------|--------|
| Speed modes | Standard (to 100 kbit/s), Fast (to 400 kbit/s), Fast mode plus (to 1000 kbit/s); **not** High speed (3.4 Mbit/s) | §12.2.2-12.2.3 |
| Roles | Master or slave; master by default; slave mode off at reset | §12.2.1-12.2.2 |
| Addressing | 7-bit default, 10-bit in master mode | §12.2.1 |
| FIFOs | 16-entry TX and 16-entry RX | §12.2.1 |
| Clock | Derived from clk_sys by programmable counters | §12.2.1.2 |
| Minimum ic_clk | 2.7 MHz standard, 12 MHz fast, 32 MHz fast mode plus | Table 1106, p. 912 |
| Minimum SCL times | high 4000 / 600 / 260 ns, low 4700 / 1300 / 500 ns for 100 / 400 / 1000 kbit/s | §12.2.14.3, p. 912 |
| Spike suppression | default 7 clk_sys cycles; set to suppress 50 ns for fast mode plus | §12.2.2, §12.2.12 |

The datasheet's recommended pad configuration for I2C is: pull-up enabled, slew rate limited, Schmitt trigger enabled. It adds a note that **external pull-ups should also be on the board**, because the internal pad pull-ups may not be strong enough to pull up external circuits ([§12.2.1.3, p. 892](sources.md#rp2350-datasheet)). Internal pull-up is 32 to 86 kohm at 3.3 V (Table 1683). The datasheet gives no pull-up sizing formula or bus-capacitance limit in the parts read *(needs source: I2C specification)*.

## UART

Two identical instances of the Arm PrimeCell PL011 (r1p5) ([§12.1, p. 871](sources.md#rp2350-datasheet)).

| Item | Value | Source |
|------|-------|--------|
| FIFOs | 32 x 8-bit TX, 32 x 12-bit RX (12 bits = data plus 4 status bits) | §12.1, §12.1.2.4-5 |
| Frame | 5, 6, 7 or 8 data bits; 1 or 2 stop bits; parity programmable; so 8N1 is supported | §12.1 |
| Flow control | Optional hardware RTS/CTS | §12.1 |
| Not supported | Modem mode and IrDA mode of the PL011 | §12.1 |
| Baud divisor | UARTCLK / (16 x baud), 16-bit integer plus 6-bit fraction; UARTCLK is clk_peri | §12.1.3.2.1, p. 874 |
| Maximum baud | UARTCLK / 16, quoted as 7.8 Mbaud at 125 MHz | §12.1.1, p. 872 |
| UARTCLK limits | at least 16 x the maximum baud; at most 16 x 65535 x the minimum baud; no more than 5/3 times PCLK | §12.1.3.1, p. 873 |
| Receive sampling | Majority vote of three samples around the middle of each bit | §12.1.3.2.2 |

Baud accuracy at 115200 depends on the clk_peri frequency set in software, which the chip datasheet does not fix for our code *(needs source: Pico SDK defaults)*. The datasheet does not state a default baud rate of 115200; that figure appears only in an example comment about the Pico SDK default ([§11.6.3, PIO UART TX example](sources.md#rp2350-datasheet)).

## Errata that matter to us

Appendix D lists the errata ([pp. 1351-1368](sources.md#rp2350-datasheet)); Appendix C maps them to chip steppings A2, A3 and A4 ([pp. 1349-1350](sources.md#rp2350-datasheet)). The stepping is shown on the package marking, in the CHIP_ID.REVISION register, or through the SDK call `rp2350_chip_version()`. The Pico 2 datasheet does not say which stepping ships on the board *(needs source)*.

| ID | One-line paraphrase | Revision |
|----|---------------------|----------|
| RP2350-E9 | Bank 0 GPIO pads (GPIO0 to 47) leak extra current (typically about 120 uA, holding the pad near 2.2 V) when the input buffer is enabled, the output is off and the voltage sits in the undefined region between VIL and VIH. The internal pull-down cannot overcome it. A source of 8.2 kohm or less overcomes it; the internal pull-up still works | Affects A2, fixed in A3 |
| RP2350-E3 | In QFN-60 only, the Non-secure access mask maps to the wrong pad registers | Affects A2, fixed in A3 (only matters if Non-secure pad access is used) |

**No errata entry in the datasheet names I2C or UART behaviour.** The only mention of UART in the errata appendix is about disabling UART boot mode in BOOTSEL (security errata). Practical meaning of E9: do not rely on the internal pull-down for a floating input on a stepping A2 chip. Our UART RX and I2C lines are driven or pulled up, so the effect is limited. The workaround is to clear the pad input enable when pull-down behaviour is needed ([Appendix D.5.1, pp. 1358-1359](sources.md#rp2350-datasheet)).

## Hardware security blocks (not relied on)

- **TRNG**: Arm IP block; the datasheet lists compliance with FIPS 140-2, BSI AIS-31 and NIST SP 800-90B and about 7.5 kbit/s of entropy at 150 MHz core clock ([§12.12.1, p. 1122](sources.md#rp2350-datasheet)).
- **SHA-256 accelerator**: present ([§12.13, p. 1131](sources.md#rp2350-datasheet)).

Our crypto stays on the Pi 4 and does not use these; this is a one-line note only.

## What this changes for our wiring

- **Are GPIO pins 5 V tolerant?** Yes for GPIO0 to GPIO25 (type FT), **only while IOVDD is powered at 3.3 V**: input up to 5.5 V is allowed (VIH max 5.5 V, absolute maximum 5.5 V). No for GPIO26 to 29 (standard pads, absolute maximum IOVDD + 0.5 V). Our wiring is 3.3 V logic anyway, so this is a safety margin, not a requirement. do not feed 5 V into the board's 3V3 pin. This resolves the gap on the [Pico 2](pico-2.md) page. The Pico 2 board datasheet's own wording about GPIO26 to 29 (3.3 V plus about 300 mV) agrees with the standard-pad limit here.
- **3.3 V Pi 4 output into a Pico input.** Pico VIH min is 2.0 V and VIL max is 0.8 V at IOVDD = 3.3 V (Table 1683). The Pi 4 output high is at least about 2.9 V (3.3 V minus 0.4 V at 2 mA, our arithmetic from [Raspberry Pi 4](raspberry-pi-4.md)), which is 0.9 V above the Pico VIH min of 2.0 V. The Pi 4 output low is at most 0.4 V at 2 mA (same page), below the Pico VIL max of 0.8 V. Both levels fit. In the other direction, Pico VOH is at least 2.62 V and VOL at most 0.5 V under the stated load; the Pi 4 input needs VIH min 2.0 V and VIL max 0.8 V, so both levels fit with margin at the default 4 mA drive and a light UART load.
- **Which GPIOs are UART0 and I2C0?** GP0 is UART0 TX and GP1 is UART0 RX (function F2). GP4 is I2C0 SDA and GP5 is I2C0 SCL (function F3). So the Build Guide assignment (GP0/GP1 UART0, GP4/GP5 I2C0) is valid on the chip. Note GP4/GP5 are also UART1 TX/RX (F2) and GP0/GP1 are also I2C0 SDA/SCL (F3), so firmware must select the function it wants. The physical pin numbers of these GPIOs on the board remain a [Pico 2](pico-2.md) figure question.
- **I2C speed and pull-ups.** The controller supports 100 kHz and 400 kHz (and 1 MHz fast mode plus); either needs clk_sys of at least 12 MHz for 400 kHz (ic_clk minimum), which is far below the 150 MHz maximum clock. The chip has programmable internal pull-ups (32 to 86 kohm), but the datasheet itself says external pull-ups should be fitted because the internal ones may be too weak. So: use external pull-ups to 3.3 V (many MPU-6050 breakout boards already carry them *(needs source: see [MPU-6050](mpu-6050.md))*), and enable the internal pull-up only as a supplement. 400 kHz is not limited by the chip for one IMU; the sensor's own maximum is on the [MPU-6050](mpu-6050.md) page.
- **UART baud.** The PL011 maximum is UARTCLK / 16 (7.8 Mbaud at 125 MHz), so 115200 8N1 is about 1.5 percent of the ceiling. 8N1 is supported (8 data bits, parity programmable, 1 stop bit). 32-byte FIFOs on both sides.
- **Errata.** No I2C or UART erratum exists. Only E9 (GPIO leakage on stepping A2, fixed in A3) is of passing interest.
