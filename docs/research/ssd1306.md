# SSD1306 OLED Driver

**Summary**: The Solomon Systech SSD1306 controller behind the 128 x 64 OLED that Pico B drives over I2C: I2C
address and write format, timing, display memory layout, supply and power sequence, the commands a driver needs, and
what the (preliminary) datasheet leaves out. It is the relay node's display.

**Sources**: [ssd1306-datasheet](sources.md#ssd1306-datasheet)

**Last updated**: 2026-10-11

---

All values are **spec** values from the SSD1306 "Advance Information" datasheet (dated Apr 2008). The document says
it describes a new product and is subject to change, so it may not match a module sold today exactly. Section numbers are
the datasheet's.

## What it is

A single-chip controller and driver for a 128 x 64 monochrome OLED panel. It has its own display RAM (GDDRAM) and
oscillator, a 256-step contrast control, and can be driven over 8-bit parallel (6800 or 8080), 3- or 4-wire SPI, or
I2C ([ssd1306-datasheet](sources.md#ssd1306-datasheet) §1, §8.1). Our module uses I2C, so the other interfaces are
ignored here.

## I2C interface (§8.1.5, §13)

| Item | Value | Notes |
|------|-------|-------|
| Slave address | `0111100` (`0x3C`) with SA0 low, `0111101` (`0x3D`) with SA0 high | 7-bit; in I2C mode the D/C# pin acts as SA0 |
| Pull-ups | SDA and SCL must be connected to pull-up resistors | stated in §8.1.5 |
| Clock cycle time | at least 2.5 µs | so about 400 kHz at most (§13, Table 13-6) |
| Rise and fall time, SDA and SCL | at most 300 ns each | |
| Start hold time, stop setup time | at least 0.6 µs | |
| Idle time between transmissions | at least 1.3 µs | |
| Data setup time | at least 100 ns | |
| Reset | `RES#` pin; the chip is initialized while it is low | §8.5 |

Write sequence (§8.1.5.2): start condition, slave address with the R/W# bit at 0, then a **control byte**, then one or
more data bytes, then stop. The control byte has a Co bit, a D/C# bit and six zeros. D/C# = 0 means the following
bytes are **commands**; D/C# = 1 means they are **display data** written to GDDRAM. Co = 0 means only data bytes
follow. The chip acknowledges every byte. The column pointer **increments automatically** after each data write.

The datasheet says the `SDAIN` and `SDAOUT` pins are tied together to act as SDA, and that panel track
resistance with the pull-up can stop an acknowledge reaching a valid low level (§8.1.5). That is a chip-level detail;
what a finished module does is *(needs source: the module's documentation)*.

## Display memory (§8.7)

- GDDRAM is 128 x 64 bits, organized as **8 pages** (PAGE0 to PAGE7) of 128 columns. A page covers 8 rows.
- One data byte fills the 8 pixels of one column in the current page: **bit D0 is the top row, D7 the bottom**.
  A full frame is 128 x 8 = 1,024 bytes.
- Segment (column) and common (row) re-mapping and a display start line can flip or shift the image by command, so
  a module mounted upside down is fixed in software, not by rewiring.

**Estimate (ours):** sending 1,024 data bytes at 400 kHz with 9 clock cycles per byte takes about
1,024 x 9 / 400,000 = 23 ms, ignoring the address and control bytes and bus gaps. That bounds how fast a
full-screen update can be; our display shows a count and one sample, so far less is needed, but it limits the
"OLED update delay" measurement ([scope](../scope.md)).

## Reset state (§8.5)

After a reset the display is **off**, the display mode is 128 x 64, mapping and scan direction are normal, the start
line and column counter are 0, the contrast register is `0x7F`, and the display shows RAM (normal mode, equal to
command `0xA4`). The chip does not light the panel until it is told to.

## Supply and power sequence (§8.9)

| Supply | Range | Purpose |
|--------|-------|---------|
| `VDD` | 1.65 to 3.3 V | logic |
| `VCC` | 7 to 15 V | panel driving |
| `VBAT` | 3.3 to 4.2 V | input to the on-chip charge pump, which makes about 7.5 V for `VCC` (application note) |

Recommended **power-on**: apply `VDD`; when stable, pull `RES#` low for at least 3 µs and release it; wait at least 3 µs
and apply `VCC`; when `VCC` is stable send command `0xAF` (display on); the outputs turn on after about 100 ms.
**Power-off**: send `0xAE` (display off), remove `VCC`, then remove `VDD` after about 100 ms. `VCC` must not be
left on without `VDD`, and the supply pins **must never be pulled to ground** (§8.9 notes).

A hobby module normally carries the charge-pump capacitors and a regulator, so it is fed 3.3 V or 5 V and the
internal charge pump is switched on by command (`0x8D`). **The datasheet's chip supply ranges say nothing about
what a particular module accepts**, so confirm the module's supply range (and whether it already has I2C
pull-ups and a reset circuit) before connecting it to the Pico's 3.3 V pin (Build Guide).

## Commands a driver needs

Command bytes are sent with D/C# = 0 in the control byte (§9, Table 9-1). The table lists the command codes; **this
page does not give a working initialization order or the bit values for a particular panel**, because the datasheet's
initialization flow chart is a picture (application note Figure 2) *(needs source)*.

| Hex | Command | Notes |
|-----|---------|-------|
| `0xAE` / `0xAF` | Display off / on | |
| `0x81` + byte | Set contrast | reset value `0x7F` |
| `0xA4` / `0xA5` | Display from RAM / entire display on (ignores RAM) | |
| `0xA6` / `0xA7` | Normal / inverse display | |
| `0x20` + A[1:0] | Memory addressing mode | `00` horizontal, `01` vertical, `10` page (§10.1.3) |
| `0x21` + start, end | Column address range | |
| `0x22` + start, end | Page address range | |
| `0xB0` to `0xB7` | Page start address (page mode) | |
| `0x40` to `0x7F` | Display start line | |
| `0xA0` / `0xA1` | Segment re-map | column flip |
| `0xC0` / `0xC8` | COM scan direction | row flip |
| `0xA8` + A[5:0] | Multiplex ratio | |
| `0xD3` + A[5:0] | Display offset | |
| `0xDA` + A[5:4] | COM pins hardware configuration | |
| `0xD5`, `0xD9`, `0xDB` | Clock divide and oscillator, pre-charge period, `VCOMH` level | |
| `0x8D` + A[7:0] | Charge pump setting | bit A[2] controls the pump (application note) |

Hex values and operand bit meanings for the multiplex ratio, COM pins and charge pump are in the datasheet's command
descriptions (§10) and application note; check them there when writing the driver.

## What the datasheet does not say

- A tested initialization sequence, the correct COM pin configuration for a given module, or the charge pump bit
  values; these come from the panel and module vendor *(needs source)*.
- How a finished module wires `SA0`, reset and pull-ups. Modules differ.
- Anything about clones of this chip (some modules use a different controller with the same pin names); the
  `0x3C` address is only a hint about the controller.

## How this bears on our wiring

Pico B drives the OLED on I2C0, GP4 (SDA, pin 6) and GP5 (SCL, pin 7), 3.3 V logic
([Pico 2 pinout](pico-2-pinout.md), [RP2350](rp2350.md)):

| Item | Result |
|------|--------|
| Address `0x3C` or `0x3D` | Set by SA0; check the module's solder pad or jumper and record the address in `evidence/L3_record.md` |
| I2C speed | 100 kHz or 400 kHz; 400 kHz is this chip's ceiling and the Pico's fast mode |
| Pull-ups | The chip needs them, and the RP2350's internal pull-ups may be too weak ([RP2350](rp2350.md)); check whether the module has them |
| Supply | 3.3 V from Pico pin 36 is within the chip's logic range, but the module's own regulator and panel supply decide whether 3.3 V is enough |
| Power sequence | Handled by the module in most cases; software should still send display-off before power-down |
