# SP 800-232 (Ascon Standard)

**Summary**: Source summary of NIST SP 800-232 (August 2025): the Ascon-AEAD128
authenticated cipher we use for every packet, plus Ascon-Hash256, Ascon-XOF128 and
Ascon-CXOF128.

**Sources**: [sp-800-232](sources.md#sp-800-232)

**Last updated**: 2026-10-08

---

## What it is

The lightweight-cryptography standard for constrained devices, built on the Ascon
permutation. It specifies one AEAD scheme (Ascon-AEAD128, based on ASCON-128a with a new
IV and little-endian byte order), one hash and two XOFs
([sp-800-232 §1](sources.md#sp-800-232)).

## Takeaways for this project

1. Each encrypted packet carries exactly a 16-byte tag of expansion. Our 16-byte nonce
   is never sent: it is rebuilt from epoch, direction and counter.
2. Nonces must never repeat under one key (R3). This is our crypto rule 4.
3. Truncated tags are allowed down to 32 bits, but under 64 bits they need a risk
   analysis, and every decryption failure should force a rekey.
4. Ascon-XOF128 has no approved key-derivation use yet (§6). This is evidence for the
   KDF decision.
5. The per-key limits are far beyond a mission's traffic, but R7 gives a spec basis for
   rekeying after too many decryption failures.
