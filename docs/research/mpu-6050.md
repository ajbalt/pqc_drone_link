# MPU-6050

**Summary**: The InvenSense MPU-6050 six-axis motion sensor that Pico A reads over I2C: supply and logic
levels, I2C address and speed, scale factors, sample rates, current and what is missing from the datasheet. It
is the rover's real sensor.

**Sources**: [mpu-6050-datasheet](sources.md#mpu-6050-datasheet)

**Last updated**: 2026-10-11

---

All values are **spec** values from the MPU-6000/MPU-6050 Product Specification, Revision 3.4 (19 Aug 2013),
at 25 °C unless stated. The datasheet says its electrical characteristics are based on design analysis and
simulation and may change ([mpu-6050-datasheet](sources.md#mpu-6050-datasheet) §1).

## What it is

A 3-axis gyroscope and 3-axis accelerometer with a temperature sensor. The MPU-6050 supports **I2C only**; the
MPU-6000 variant also supports SPI. The MPU-6050 has a separate `VLOGIC` pin that sets the I2C logic levels.

## Power and logic levels

| Item | Value | Unit | Notes |
|------|-------|------|-------|
| `VDD` supply | 2.375 to 3.46 | V | §6.3. **Never connect the bare chip to 5 V** |
| `VLOGIC` | 1.71 up to `VDD` | V | MPU-6050 only; must be at or below `VDD` at all times (§6.3) |
| Input high (SCL, SDA, AD0) | at least 0.7 × `VLOGIC` | V | about 2.31 V at 3.3 V (§6.4) |
| Input low | at most 0.3 × `VLOGIC` | V | about 0.99 V at 3.3 V |
| Operating current, gyro + accelerometer, DMP off | 3.8 | mA | typical, §6.3; gyro only 3.6 mA, accelerometer only 0.5 mA |
| Specified temperature range | -40 to +85 | °C | §6.3 |

A 3.3 V Pico output (see [Pico 2](pico-2.md)) is above the input-high threshold. Breakout boards (such as
the common GY-521) often add a regulator and pull-ups. **That is not in this datasheet**, so confirm the
actual breakout's voltage compatibility and pull-ups (Build Guide) before connecting. The 3.8 mA current is
small against a Pico's 3.3 V output, whose limit is a *(needs source)* until the Pico 2 datasheet is read.

## I2C

| Item | Value | Notes |
|------|-------|-------|
| Speeds | 100 kHz standard, 400 kHz fast | 400 kHz is the maximum bus speed (§6.4, §9.2) |
| Slave address | `0x68` with AD0 low, `0x69` with AD0 high | 7-bit `b110100X` (§9.2) |
| Pull-ups | SDA and SCL need pull-ups to `VDD` (§9.2) | the chip has none to provide |
| Role | always an I2C slave | |

Two sensors can share a bus using the two addresses. We use one.

## Scale factors (what the 16-bit values mean)

| Sensor | Full-scale setting | Range | Sensitivity | Unit |
|--------|-------------------|-------|-------------|------|
| Accelerometer | `AFS_SEL`=0 | ±2 g | 16,384 | LSB/g |
| | `AFS_SEL`=1 | ±4 g | 8,192 | LSB/g |
| | `AFS_SEL`=2 | ±8 g | 4,096 | LSB/g |
| | `AFS_SEL`=3 | ±16 g | 2,048 | LSB/g |
| Gyroscope | `FS_SEL`=0 | ±250 °/s | 131 | LSB per °/s |
| | `FS_SEL`=1 | ±500 °/s | 65.5 | LSB per °/s |
| | `FS_SEL`=2 | ±1000 °/s | 32.8 | LSB per °/s |
| | `FS_SEL`=3 | ±2000 °/s | 16.4 | LSB per °/s |

Both ADCs are 16 bits. These match the values our record format assumes at ±2 g and ±250 °/s
([telemetry format](../telemetry_format.md)). Gyro sensitivity tolerance is ±3% at 25 °C (§6.1); accelerometer
initial calibration tolerance is ±3% (§6.2), and the zero-g offset on X and Y is ±50 mg initially, so absolute
accuracy is limited. Our task is relative motion (tilt shows a change), not calibrated measurement.

The temperature sensor has a sensitivity of 340 LSB/°C and an offset of -521 LSB at 35 °C (§6.3). We do not use it.

## Sample rates

| Item | Value | Notes |
|------|-------|-------|
| Accelerometer output data rate | programmable, 4 to 1,000 Hz | §6.2 |
| Gyroscope output data rate | programmable, 4 to 8,000 Hz | §6.1 |
| Low-pass filter | accelerometer 5 to 260 Hz; gyro up to 256 Hz | |
| Gyroscope start-up time | about 30 ms | `DLPFCFG`=0 (§6.1) |
| FIFO | 1,024 bytes | lets the host read in bursts (§5, §7.17) |

Our 10 Hz sampling (Build Guide gate L2) is well within the range. Pico A can poll at 10 Hz directly, so the
FIFO is optional.

## What is missing (needed for the driver)

The datasheet **does not contain the register map**. It repeatedly refers to a separate document, the
"MPU-6000/MPU-6050 Register Map and Register Descriptions". That document is needed for:

- the power-management register (the chip's sleep or reset state at power-up, and how to wake it; §7.4 gives only the power-on sequencing)
- the configuration registers that choose the sample rate, the low-pass filter and the full-scale ranges
- the addresses and byte order of the data registers (§7.16 only points to them)
- the identity register used to check the sensor is present

None of these are stated here, so no register addresses are given on this page *(needs source)*. Add the register
map document to the source drive before writing the driver (gate L2).
